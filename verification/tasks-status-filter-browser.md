# تحقق فلتر حالات المهام

## 2026-08-17 — اختبار المتصفح المحلي

فُتحت صفحة `/tasks` عبر `http://localhost:3004/tasks`. ظهر عنصر اختيار مستقل يحمل `aria-label="فلترة حسب الحالة"` وبداخله الخيارات العربية «كل الحالات»، «لم تبدأ»، «جارية»، و«مكتملة»، إلى جانب فلاتر الأولوية والتصنيف الحالية.

عند اختيار «جارية» ظهر صف واحد فقط لمهمة «تحضير عرض تقديمي للمشروع»، وهي الحالة الوحيدة `in-progress` في بيانات الاختبار. أعاد العرض توزيع الأعمدة الزمنية مع إبقاء بطاقة المهمة وبيانات المشروع والهدف وروابطها سليمة، وظهر زر «مسح الفلاتر».

سيُستكمل الاختبار باختيار «لم تبدأ» و«مكتملة» ثم إعادة الفلتر إلى «كل الحالات» دون إنشاء أو تعديل بيانات دائمة.

اختيار «لم تبدأ» عرض أربع مهام فقط: «اختبار مهمة يومية»، «حجز موعد الدكتور»، «شراء مستلزمات البيت»، و«قراءة فصل من الكتاب»، موزعة حسب الموعد. ثم اختيار «مكتملة» عرض مهمتي «مراجعة تقرير الشغل الأسبوعي» و«الرد على رسائل البريد المتأخرة» فقط، مع أزرار «إعادة فتح المهمة» سليمة. لم تُعدّل أي مهمة ولم تظهر أخطاء تطبيقية.

أعيدت الحالة إلى «كل الحالات»، فعاد العرض إلى خمس مهام في عمود النهاردة ومهمة في «بكرة» ومهمة في «الأسبوع ده»، وعاد زر «مسح الفلاتر» للاختفاء. انتهت الجلسة دون تعديل على localStorage أو حالة أي مهمة.

**النتيجة:** PASS بصريًا وتفاعليًا للحالات `todo` و`in-progress` و`done`، مع بقاء الفلاتر الأخرى والتصميم RTL متوافقين.
