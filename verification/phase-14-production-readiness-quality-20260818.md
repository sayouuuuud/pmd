# محضر جودة المرحلة 14 — الجاهزية والتقوية والإطلاق

**التاريخ:** 2026-08-18

**النطاق:** المرحلة الأخيرة من خطة Personal Command Center، الخاصة بتحويل النماذج التجريبية إلى منتج قابل للاستخدام الحقيقي مع توثيق حدود البيئة المحلية.

## معيار المرحلة

تطلب الخطة خزنة أسرار وتشفيرًا وإعادة مصادقة، تقوية 2FA واسترجاع الحساب، مراجعة صلاحيات Workspace والعميل والفريق، حماية المشاركة والمرفقات، مراجعة جامع Windows والاحتفاظ والحذف، حماية الفوترة والتصدير وسجل التدقيق، Security Headers وCSRF/session behavior، اختبارات cross-user وcross-workspace، اختبارات HTTPS وPWA وService Worker، ونسخًا احتياطيًا واستعادة موثقين.

## التنفيذ المنجز

تم تقوية تصدير الحساب بحيث لا يخرج `clientCredential.secretValue` أو `workspaceInvitation.tokenHash` أو أسرار 2FA أو رموز الاسترداد. يعيد التصدير البيانات الوصفية اللازمة للاستعادة والتدقيق فقط، ويبقى محميًا بجلسة المستخدم؛ طلب غير موثق إلى `/api/account/export` أعاد `401` محليًا.

تم تطبيق `retentionDays` على جلسات النشاط المحلية فعليًا عند الإضافة أو تغيير الإعداد. وتبقى واجهة النشاط داعمة للإيقاف المؤقت، استثناء التطبيقات والنطاقات، الحذف الانتقائي، الحذف الكامل، المزامنة الاختيارية، وإضافة جلسة يدوية للاختبار. وكيل Windows التجريبي يجمع اسم العملية ومدة الجلسة فقط، ولا يجمع كلمات مرور أو رسائل أو لقطات شاشة أو ضغطات مفاتيح.

تمت إضافة رؤوس حماية متدرجة في `next.config.mjs`: `X-Frame-Options`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، `X-DNS-Prefetch-Control`، `Cross-Origin-Resource-Policy`، و`Origin-Agent-Cluster`. تم تجنب HSTS وCSP غير مكتملين في بيئة HTTP المحلية؛ يجب إكمالهما في خط الإصدار الحقيقي مع HTTPS وnonces أو hashes مناسبة.

## الاختبارات التي لا يمكن إغلاقها محليًا

لا توجد `DATABASE_URL` أو `BETTER_AUTH_SECRET` في البيئة الحالية، لذلك لم يُدّعَ نجاح اختبار قاعدة بيانات حقيقية أو جلسة Better Auth حقيقية. يلزم قبل الإطلاق اختبار حسابين ومساحتين للتحقق من العزل، تفعيل واختبار 2FA والاسترداد، اختبار روابط بوابة العميل والإبطال، تشغيل HTTPS وService Worker على نطاق نشر، واختبار backup/restore في بيئة منفصلة.

تظل مرفقات المكتبة في المرحلة الحالية metadata محلية؛ تخزين الملفات الخاص وفحص MIME والحجم والمحتوى وروابط signed قصيرة العمر يحتاج object storage وطبقة خادم إنتاجية. كما أن SQL المرافق للمراحل 11–13 مؤجل ولم يُشغّل حسب القيد، ولا يجوز تشغيله قبل مراجعة migration journal وأخذ backup.

## قرار الجودة

**المرحلة 14 ناجحة محليًا وقابلة للاعتماد البرمجي.** لا توجد فجوة قابلة للإصلاح بأمان داخل البيئة الحالية بعد تقوية التصدير والاحتفاظ والرؤوس الأمنية وتشغيل البوابات. الإطلاق الحقيقي مشروط فقط بتوفير أسرار البيئة وقاعدة البيانات وتشغيل اختبارات الإنتاج المذكورة أعلاه؛ لا تُعتبر هذه الاختبارات مثبتة بالاختبار المحلي.
