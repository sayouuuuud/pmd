# اختبار تحرير المهام

- التاريخ: 2026-08-16
- المسار: `/tasks`
- البيئة: خادم التطوير المحلي على المنفذ 3004، مع fallback المحلي عند غياب credentials.

## السيناريو

فُتح محرر المهمة `task-1`، ثم عُدّل العنوان مؤقتًا إلى «مراجعة تقرير الشغل الأسبوعي — اختبار تحرير»، والموعد إلى «بكرة»، والتصنيف إلى «اختبار»، والأولوية إلى «منخفضة». بعد الحفظ انعكست القيم الأربع في البطاقة مباشرة داخل قائمة المهام.

أُعيد فتح المحرر بعد ذلك، وأُعيدت القيم إلى «مراجعة تقرير الشغل الأسبوعي»، و«النهاردة»، و«شغل»، و«عالية»، ثم حُفظت الاستعادة. عادت البطاقة إلى بياناتها الأصلية ولم تُترك بيانات اختبارية في الحالة.

## النتيجة

نجح المسار المتفائل لتحرير المهمة عبر `updateTask`، وظهرت التغييرات في الواجهة العربية RTL. لم تظهر أخطاء JavaScript أو أخطاء مزامنة في وحدة التحكم أثناء دورة التحرير والاستعادة.

## النطاق والحدود

الاختبار يغطي التحرير المحلي وواجهة API الحالية عند توفرها، مع fallback إلى localStorage عند غياب قاعدة البيانات. لم يُنفّذ اختبار مصادقة متعدد المستخدمين في هذه الدورة لأن credentials غير متاحة في البيئة الحالية.

## الحكم

PASS — تحرير عنوان المهمة وأولويتها وموعدها وتصنيفها يعمل، والاستعادة إلى الحالة الأصلية مؤكدة.
