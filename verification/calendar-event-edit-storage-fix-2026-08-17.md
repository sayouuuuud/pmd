# تحقق التقويم — تحرير الأحداث وثبات التخزين

**التاريخ:** 2026-08-17

## النطاق

اختبار دورة الحدث اليدوي في `/calendar`، وإغلاق فجوة عدم وجود تحرير، والتحقق من عدم فقد الأحداث المحلية عند إعادة تحميل الصفحة.

## الإصلاحات

- إضافة زر **تعديل الحدث** للأحداث اليدوية فقط.
- إعادة استخدام نموذج الحدث نفسه في وضعي الإنشاء والتحرير مع رسائل عربية واضحة.
- إرسال تحديثات الأحداث البعيدة عبر `PATCH /api/calendar-events/[id]` مع الإبقاء على التحديث المحلي عند غياب الجلسة أو قاعدة البيانات.
- إصلاح سباق تهيئة `localStorage` الذي كان يكتب قائمة فارغة في أول تحميل قبل اكتمال قراءة الأحداث المحلية.

## الاختبار التفاعلي

| الخطوة | النتيجة |
|---|---|
| فتح نموذج «حدث جديد» | نجح |
| إنشاء «جلسة تخطيط اختبارية» بتاريخ 2026-08-18 الساعة 15:30 مع وصف عربي | نجح، ظهرت بطاقة الحدث |
| التحقق من زر التعديل | نجح، ظهر زر `تعديل الحدث` للأحداث اليدوية دون العناصر المجمعة |
| فتح نموذج التحرير | نجح، امتلأت القيم الحالية تلقائيًا وظهر عنوان «تعديل حدث» |
| تعديل العنوان والوقت إلى 16:15 والوصف | نجح، حدثت البطاقة نفسها دون تكرار |
| حذف الحدث الاختباري | نجح، اختفت البطاقة وبقيت أحداث التذكيرات الأصلية |
| فحص API في بيئة بلا جلسة | أعاد 401 عربيًا، واستمر fallback المحلي دون كسر الصفحة |
| فحص البناء | نجح TypeScript وESLint وdiff check وNext build |

## ملاحظات

ظهرت مشكلة حقيقية أثناء الاختبار: كانت الأحداث المحلية تختفي بعد إعادة التحميل لأن تأثير الحفظ كان يكتب `[]` قبل انتهاء تأثير القراءة الأولي. عولجت بإضافة حالة `storageLoaded` تمنع الحفظ حتى اكتمال التهيئة.

لم تُحذف أي بيانات مستخدم أصلية. تمت إزالة سجل الاختبار بعد اكتمال الدورة.
