## تقوية المرحلة 14 المنفذة

أصبح تصدير الحساب يختار الحقول الآمنة بدل تصدير السجلات الخام لبيانات اعتماد العملاء أو الدعوات. لا يخرج `clientCredential.secretValue` ولا `workspaceInvitation.tokenHash` ولا أسرار إعداد 2FA أو رموز الاسترداد. يحتفظ التصدير بحالة الميزة والبيانات الوصفية اللازمة للاستعادة والتدقيق دون تحويل النسخة الاحتياطية إلى مخزن أسرار.

تم تطبيق `retentionDays` فعليًا داخل دورة نشاط Windows المحلية عبر تنظيف الجلسات القديمة عند الإضافة أو تغيير الإعداد، مع حد آمن للمدى وحذف محلي صريح. كما بقيت خيارات الإيقاف المؤقت، الاستثناءات، الحذف الانتقائي، والحذف الكامل واضحة في الواجهة.

أضيفت رؤوس `X-Frame-Options` و`X-Content-Type-Options` و`Referrer-Policy` و`Permissions-Policy` و`X-DNS-Prefetch-Control` و`Cross-Origin-Resource-Policy` و`Origin-Agent-Cluster` إلى إعداد Next.js. لم يُضف HSTS أو CSP غير مكتمل لأن التطبيق المحلي الحالي يعمل دون HTTPS ولأن سياسة CSP تحتاج nonces أو hashes من خط الإصدار الحقيقي.

## ما ينتظر بيئة الإنتاج أو قرارًا تشغيليًا

| البند | سبب عدم اعتباره مغلقًا 100% محليًا | الإجراء المطلوب قبل الإطلاق |
|---|---|---|
| خزنة الأسرار والتشفير وإعادة المصادقة | لا يوجد مفتاح تشفير إنتاجي أو DATABASE_URL في البيئة الحالية، ولا يجوز اختراع سر داخل المستودع | تفعيل تشفير server-side بمفتاح خارج المستودع، وإضافة إعادة مصادقة قبل القراءة أو التعديل. |
| Better Auth و2FA الحقيقي | الموجود تجريبي خلف Feature Flag | تفعيل الأسرار، اختبار التسجيل والدخول و2FA والاسترداد وحالات فقدان الجهاز بحساب حقيقي. |
| cross-user وcross-workspace isolation | بوابات المصدر نجحت، لكن لا توجد جلسات وقاعدة بيانات حقيقية لتشغيل اختبارين منفصلين | تشغيل اختبارات تكامل بحسابين ومساحتين، والتأكد من رفض كل ID خارج الملكية. |
| بوابة العميل والمشاركة وإبطال الوصول | التدفق المحلي موثق، أما الروابط العامة الحقيقية فتحتاج قاعدة بيانات وبيئة نشر | اختبار إنشاء الرابط، فتحه بحساب صحيح/خاطئ، الإبطال، وانتهاء الصلاحية. |
| فحص مرفقات الملفات | المرفقات الحالية metadata محلية؛ لا يوجد object storage أو antivirus production pipeline | فرض allowlist MIME/حجم على الخادم، تخزين خاص، فحص محتوى، وروابط signed قصيرة العمر. |
| HTTPS وPWA وService Worker | تم اختبار PWA محليًا فقط | نشر HTTPS، اختبار التسجيل والتحديث والعمل offline على Chrome/Edge وقياس مسار الاستعادة. |
| النسخ الاحتياطي والاستعادة | export/import المحلي موجود، لكن استعادة Neon لم تُشغّل | اختبار backup دوري، restore في بيئة منفصلة، والتحقق من عدم تضمين الأسرار. |
| SQL المؤجل | ملفات SQL موجودة ولم تُشغّل حسب القيد | مراجعة migration journal ثم تشغيل الملفات بترتيبها في Neon بعد أخذ backup. |

## قرار الاعتماد

المنتج **جاهز للاعتماد المحلي وإغلاق نطاق التنفيذ البرمجي**: جميع بوابات TypeScript وESLint وWebpack والمسارات والاستجابة وإمكانية الوصول نجحت، ومسارات النشاط والتصدير والرؤوس الأمنية اختُبرت محليًا. أما **الإطلاق الحقيقي النهائي** فيظل مشروطًا بتوفير أسرار البيئة وقاعدة البيانات وتشغيل اختبارات العزل و2FA وHTTPS والتخزين الخاص للمرفقات؛ وهذه ليست فجوات يمكن إثباتها أو إصلاحها بأمان داخل بيئة لا تحتوي credentials.
