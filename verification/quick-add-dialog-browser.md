# تحقق Quick Add بعد ربطه بـ Dialog المشترك

## النطاق
- الصفحة: `http://localhost:3004/`
- التغيير: استبدال غلاف نافذة «إضافة سريعة» المكرر بمكوّن `components/ui/dialog.tsx` المشترك.
- البيانات: لم يتم تأكيد أي إضافة ولم تُعدّل بيانات المستخدم.

## خطوات الاختبار والنتائج
1. فُتحت الصفحة الرئيسية وظهر زر «إضافة سريعة» بصورة سليمة.
2. فُتحت النافذة؛ ظهر عنوان «إضافة سريعة» ووصفها، مع overlay معتم وتمويه خلفي، وتحقق وجود `role="dialog"` وخصائص الوصول.
3. ظهرت تبويبات «مهمة / ملاحظة / مصروف / فيلم»، وحقل المهمة، واختيار المشروع، وأزرار «إلغاء» و«مراجعة قبل الحفظ» دون أخطاء runtime.
4. أُغلق Dialog عبر مفتاح `Escape` وعادت الصفحة إلى حالتها الأصلية، ما يثبت أن منطق الإغلاق المشترك يعمل بدل مستمع مخصص داخل Quick Add.
5. لم يُنفذ الحفظ ولم تتغير أي مهمة أو ملاحظة أو حركة مالية أو عنصر ترفيه.

## بوابات الجودة
- `tsc --noEmit`: ناجح.
- `eslint . --no-warn-ignored`: ناجح بلا تحذيرات.
- `git diff --check`: ناجح.
- `next build`: ناجح. ظهر تحذير Next.js المعلوماتي المعتاد بشأن convention الخاص بـ`middleware` فقط.

## الملاحظات
- حافظ التغيير على RTL، كروت النظام المستديرة، ألوان Semantic Tokens، ونصوص Quick Add الحالية.
- لم يُختبر حفظ عنصر فعلي لأن السيناريو المطلوب كان التحقق من الغلاف المشترك دون إدخال بيانات جديدة.
- ما زال اختبار النوافذ الأخرى التي يمكن ترحيلها إلى Dialog مشترك بندًا لاحقًا إذا بقي مفتوحًا في الخطة.
