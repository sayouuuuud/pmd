**المشروع:** Personal Command Center
**تاريخ اللقطة:** 2026-08-18
**آخر commit محلي وبعيد:** `def4123` — `feat: make archive restore synchronization observable`
**حالة Git:** `main` المحلي متطابق مع `origin/main`، ولا توجد تغييرات محلية غير معتمدة في لقطة المقارنة.

## الخلاصة التنفيذية

الخطة المرفقة أوسع بكثير من نطاق الـMVP الموجود حاليًا. الأساس الشخصي اليومي، واجهة RTL، أغلب صفحات الحياة اليومية، البحث، التذكيرات، التقويم الأساسي، Workspace/Clients الأولي، التسعير الأولي، الدعوات التجريبية، و2FA التجريبي الجزئي موجودة في الريبو. لكن وجود جداول أو Routes أو واجهة أولية لا يساوي إغلاق المرحلة؛ الإغلاق يتطلب تدفقًا قابلًا للاختبار، عزل ملكية، اختبارًا بصريًا، واختبارًا إنتاجيًا عند اعتماد الخطة لذلك.

أكبر الفجوات غير المنفذة فعليًا هي **بوابة العميل والمشاركة، المكتبة والموارد والملفات، الفوترة والفواتير، جامع نشاط Windows، وطبقة التقوية النهائية**. كما توجد فجوات جزئية مهمة في 2FA، RBAC والدعوات، الربط الإنتاجي، التقويم الموحد، البحث والأرشيف الشامل، والعلاقات بين العميل والمشروع والتحديث والملف والدفعة.

> **الحكم المختصر:** الـMVP الشخصي قريب من الإغلاق، وV1 بدأ بالفعل لكنه غير مكتمل إنتاجيًا، بينما V1.5 وV2 وProduction Hardening لم تُنفذ إلا على شكل أجزاء تمهيدية محدودة.

## ما لم يُنفذ فعليًا — القائمة المباشرة

إذا كان المقصود بـ«غير منفذ» هو الميزة التي لا توجد لها شريحة تشغيلية مكتملة في الريبو، فالقائمة هي:

| الأولوية | الفجوة غير المنفذة | سبب عدم اعتبارها منفذة |
|---|---|---|
| P0 | اعتماد الخطة رسميًا داخل `EXECUTION_PLAN.md` مع feature flags موحدة | الوثيقة المرفقة ما زالت مسودة نقاش، وحدود التجريبي/الإنتاجي ليست flags موحدة لكل الميزات الحساسة |
| P0 | 2FA recovery/challenge/feature flag واختبار production | الموجود enable/verify/disable تجريبي، دون recovery واختبار جلسة حقيقية كامل |
| P0 | RBAC كامل وعزل cross-user/cross-workspace | الدعوات والأدوار الأولية موجودة، لكن مصفوفة الصلاحيات والاختبارات الشاملة غير مغلقة |
| P1 | Work Dashboard وملف العميل الكامل | Client CRUD موجود، لكن لوحة العمل والحقول والعلاقات المطلوبة غير مكتملة |
| P1 | بوابة العميل والمشاركة granular | لا توجد بوابة عميل مكتملة ولا عرض/تعليق/موافقة/إشعارات على البيانات المشتركة |
| P1 | مكتبة الموارد والملفات والمرفقات | لا توجد Resource/Library/Attachment feature مكتملة |
| P1 | نظام الفوترة والفواتير التجريبي | pricing وcollect لا يساويان invoices وquotes وline items وحالات الفاتورة والتصدير |
| P1 | التقويم الموحد لكل المصادر | التقويم الحالي لا يثبت دمج كل مصادر الخطة العميلية والمالية والمراجعات والتحديثات |
| P1 | بحث وأرشيف كاملان لكل الموارد والتحديثات والدفعات والملفات | الموجود يغطي النطاق الحالي فقط، لا العقد الموحد الكامل |
| P2 | ربط كامل بين Projects/Tasks/Updates/Files/Payments/Clients | توجد روابط أولية، لكن ليس نموذج علاقات موحدًا ومختبرًا عبر كل المسارات |
| P2 | حسابات العملاء التجريبية | لا يوجد نموذج مكتمل لبيانات الدخول المقنّعة خلف flag، ولا vault/reauth |
| P2 | Windows Agent وتحليلات النشاط | غير موجود في الريبو |
| P0 قبل الإطلاق | Production Hardening | لا توجد بوابة إطلاق ناجحة تشمل HTTPS، session حقيقي، 2FA، RBAC، portal، billing، uploads، backup، وPWA offline الكامل |

## ترتيب العمل المتبقي المقترح

الأولوية الآمنة ليست Windows أو تخزين بيانات دخول العملاء. الخطوة الأولى هي تثبيت مصفوفة النطاق والـfeature flags، ثم إغلاق 2FA التجريبي وRBAC والدعوات باختبارات حقيقية. بعد ذلك يُستكمل Work Dashboard وملف العميل والعلاقات، ثم بوابة العميل والمكتبة، ثم الفوترة. يأتي Windows Agent بعد وجود consent/pause/delete/retention وواجهة بيانات واضحة، وتُترك Screenshots وKeylogging وقراءة المحتوى لتجارب مستقلة اختيارية لا تعمل افتراضيًا. وأخيرًا تُنفذ Production Hardening وبوابة الإطلاق.

هذا الترتيب يحافظ على قاعدة المشروع الحالية: لا أسرار في الريبو، كل query محمي بملكية وجلسة، لا تشغيل لـ`drizzle-kit generate` قبل حل اختلاف journal، ولا إعلان إغلاق مرحلة دون دليل قابل للتكرار.
