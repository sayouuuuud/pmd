# محضر جودة المرحلة العاشرة — البحث والأرشيف والتذكيرات والعلاقات

**التاريخ:** 18 أغسطس 2026

**المشروع:** Personal Command Center

**نطاق المرحلة:** توسيع البحث، الأرشيف والاسترجاع، التذكيرات، العلاقات العميقة، وسجل الاقتراحات الشخصية، مع تجهيز مخطط قاعدة البيانات في ملف SQL مؤجل لا يُشغّل تلقائيًا.

## نتيجة الإغلاق

اكتمل التنفيذ المحلي للمرحلة العاشرة، واجتازت التعديلات بوابات TypeScript وESLint وبناء الإنتاج وتدقيق ملكية المسارات وتدقيق الوصول. ملف SQL الخاص بالمرحلة موجود في `sql/phase-10-search-archive-reminders-relations.sql` وموسوم بوضوح بأنه **مؤجل**؛ لم يتم تطبيقه على Neon، ولم يتم تشغيل `drizzle-kit generate` التزامًا بالقيد الخاص باختلاف سجل migrations.

## المطابقة التفصيلية

| البند | التنفيذ | الحالة |
|---|---|---|
| البحث الموحد | توسعة `global-search-dialog` ليشمل العملاء، تحديثات المشاريع، سجلات التسعير، والأحداث المحلية، مع الإبقاء على روابط السياق ومصادر البيانات الحالية | مكتمل محليًا |
| الأرشيف | الإبقاء على واجهة الأرشيف الحالية للبحث والاسترجاع والفلترة، مع توثيق جدول `archive_item` المقترح للربط الإنتاجي | مكتمل محليًا / SQL مؤجل |
| التذكيرات | استخدام عقد التذكيرات الحالي، وإضافة `workspace_id` وفهرس due/status في SQL المؤجل لعزل مساحة العمل وتحسين الوصول الزمني | مكتمل محليًا / SQL مؤجل |
| العلاقات | إضافة مخطط `entity_relation` المقترح بعلاقة مصدر/هدف وملكية `user_id` و`workspace_id` ومنع العلاقة الذاتية | SQL مؤجل |
| الاقتراحات الشخصية | إنشاء `personal-suggestions` وربطه بالمراجعة الأسبوعية، مع حالات قبول ورفض وسبب القرار وسياق المهمة أو العادة أو المشروع أو التذكير | مكتمل محليًا |
| فهرسة البحث | إضافة مخطط `search_document` وفهارس الملكية والعنوان والنص الكامل في SQL المؤجل | SQL مؤجل |
| الروابط العميقة | الحفاظ على helper الروابط المركزي المستخدم في المجالات السابقة وعدم إنشاء مسار روابط موازٍ | مكتمل |
| الملكية والخصوصية | كل الجداول المقترحة تحمل `user_id`، والجداول المرتبطة بمساحة العمل تحمل `workspace_id`، مع اشتراط مراجعة RLS قبل التشغيل | محضر ومخطط مؤجل |

## ملف SQL المؤجل

الملف `sql/phase-10-search-archive-reminders-relations.sql` يحتوي على مخطط `entity_relation` و`archive_item` و`personal_suggestion` و`search_document`، وتوسعة `reminder` بحقل مساحة العمل والفهرس المناسب. الملف محاط بـ`BEGIN` و`COMMIT` لكنه لا يُشغّل من التطبيق أو من هذا المحضر. قبل تشغيله يجب reconcile لسجل Drizzle، والتحقق من أسماء الجداول والأنواع في البيئة المنشورة، وإضافة ومراجعة سياسات RLS، ثم اختباره على staging عبر مسار migrations المعتمد.

> لا يجوز تشغيل الملف مباشرة على قاعدة الإنتاج قبل مراجعة الملكية وRLS وتعارض journal. وجود `COMMIT` داخل الملف لا يعني أنه نُفّذ.

## الحدود المعروفة

التنفيذ الحالي يغلق الشريحة المحلية والواجهية من المرحلة العاشرة، لكنه لا يدّعي تطبيق الجداول أو فهارس البحث على Neon. كما أن التذكيرات والعلاقات والبحث الإنتاجي الكامل يظلون معتمدين على إغلاق المرحلة التاسعة الخاصة بالـcredentials وتسلسل migrations. لا توجد أسرار أو بيانات اتصال داخل المستودع.

## قرار الاعتماد

**القرار:** اعتماد المرحلة العاشرة محليًا وواجهياً، مع تسجيل طبقة قاعدة البيانات كـSQL مؤجل. يمكن الانتقال إلى المرحلة التالية في نطاق local-first، بينما يبقى تفعيل Neon والمزامنة الإنتاجية شرطًا سابقًا قبل إعلان الجاهزية الإنتاجية الكاملة.
