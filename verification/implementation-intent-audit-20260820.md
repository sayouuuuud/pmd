## اختلافات تعمل لكنها تحتاج موافقتك

1. **Portal:** التنفيذ الحالي رابط محلي token داخل localStorage، بينما تصور الخطة دعوة/دخول عميل وصلاحيات server-side. يمكن اعتماد المحلي كنموذج UI فقط، لا كإغلاق للمرحلة.
2. **Library:** التنفيذ الحالي يسجل metadata للمرفقات دون رفعها. هذا مناسب prototype، لكنه مختلف جوهريًا عن «رفع مرفقات وعرضها وتخزين خاص».
3. **Billing:** التنفيذ الحالي دفتر فواتير محلي وتصدير JSON؛ تصور الخطة تدفق تجريبي كامل مرتبط بالمشروع والعميل والمالية. الاختلاف يحتاج قرارًا: هل يكفي local prototype أم يلزم Backend حقيقي؟
4. **Tasks recurrence:** التنفيذ يختزل التكرار إلى boolean ويستنتج يومي/أسبوعي من `dueLabel`. هذا يعمل بصريًا لكنه ليس نموذج تكرار حقيقي يولد نسخًا في موعدها.
5. **Workspace fallback:** عند فشل أي request تتحول بعض الإجراءات إلى localStorage بدل إظهار فشل مزامنة قابل لإعادة المحاولة. هذا يحافظ على الاستخدام لكنه قد يوهم المستخدم أن البيانات محفوظة في الحساب.
6. **مفهوم «مغلق محليًا»:** التقارير الأخيرة استخدمته لإغلاق مراحل كاملة. إن كان مقصودك أن المرحلة لا تُغلق إلا عند تحقق معيارها الحقيقي، فيجب إعادة فتح 5–14 ومعظم 6–13.
