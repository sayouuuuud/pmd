# تحقق مساحة المراجعة الأسبوعية — المكونات المشتركة

التاريخ: 2026-08-17

## النطاق

جرى ترحيل أزرار «حفظ كمسودة» و«اعتماد المراجعة» و«أضف كهمة للأسبوع» في `components/review/weekly-review-workspace.tsx` إلى `Button` المشتركة، مع الحفاظ على handlers والأنماط الحالية والـRTL.

## فحص DOM والظهور البصري

فُتحت `http://localhost:3004/review` على الخادم المحلي. ظهرت صفحة مراجعة الأسبوع والكروت العربية وخط Cairo والسياق المرتبط والمراجعة المكتوبة وقرار الأسبوع القادم بصريًا دون أخطاء. أكد فحص DOM داخل الصفحة عدم وجود عناصر تحكم خام: `rawButtons: 0`, `rawInputs: 0`, `rawSelects: 0`, `rawTextareas: 0`. وظهرت ثلاثة أزرار الدفعة ضمن المكونات المشتركة، مع أزرار shell العامة، بإجمالي `sharedButtons: 7`، كما ظهرت حقول المراجعة الثلاثة ضمن `Textarea` المشتركة (`sharedTextareas: 3`).

الأزرار المرحّلة الظاهرة هي «حفظ كمسودة»، «اعتماد المراجعة»، و«أضف كهمة للأسبوع». لم تُنفذ عملية حفظ أو إضافة مهمة قبل استكمال الاختبارات غير الدائمة.


## اختبار التفاعل

أُدخل نص مؤقت «اختبار قرار أسبوعي مؤقت» في حقل «ما هدف الأسبوع القادم؟»، فظهرت رسالة «هناك نص غير محفوظ» وتمكّن زر «أضف كهمة للأسبوع». نُقر زر «حفظ كمسودة» المرحّل، فظهرت رسالة «تم حفظ المسودة ويمكنك العودة إليها لاحقًا» وتحدث وقت الحفظ بصريًا، ما يؤكد أن handler الزر يعمل. بعد ذلك أُعيدت قيمة `personal-command-center-state-v2` إلى النسخة الملتقطة قبل الاختبار وأُعيد تحميل الصفحة؛ عادت الحقول والقرار إلى حالتها الأصلية دون بقاء النص المؤقت أو إنشاء مهمة جديدة. لم يُختبر اعتماد المراجعة لأن ذلك يغيّر الحالة النهائية عمدًا، واكتفى التحقق بوجوده كمكوّن Button وباختبار مسار الحفظ غير النهائي.


## بوابات الجودة

أظهر الفحص الساكن عدم وجود `<button>` أو `<input>` أو `<select>` أو `<textarea>` خام في الملف. نجحت بوابات `tsc --noEmit` و`eslint . --no-warn-ignored` و`git diff --check` و`next build`. اكتمل بناء الإنتاج وتوليد 25 صفحة. ظهر تحذير Next.js المعلوماتي المعتاد بشأن convention ملف `middleware`، ولم يمنع البناء.
