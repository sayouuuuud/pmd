# خطة التنفيذ المحلية قبل ربط قاعدة البيانات

## الهدف

تُنفّذ الفجوات المتبقية في Personal Command Center على مراحل محلية أولًا. تستخدم المراحل 1–8 واجهات وعقودًا وبيانات تجريبية واقعية، مع إبقاء حدود الملكية وRBAC في المسارات والـadapters. لا تُعد هذه المراحل دليلًا على اتصال Neon أو جاهزية الإنتاج.

## ترتيب المراحل

| المرحلة | النطاق | معيار الإغلاق |
|---|---|---|
| 1 | تثبيت النطاق والعقود المحلية | عقود TypeScript موحدة، سجل خطة محدث، حدود local-first موثقة، ونجاح بوابات الجودة |
| 2 | Work Dashboard وملف العميل الكامل | لوحة عملية وملف عميل غني يعملان عبر local repository مع حالات loading/empty/error/archive |
| 3 | بوابة العميل والمشاركة granular | مشاركة قابلة للإبطال، صلاحيات منفصلة، تعليقات وموافقات، دون تسريب عناصر غير مشتركة |
| 4 | مكتبة الموارد والملفات | موارد وروابط وملفات محلية، وسوم وبحث وأرشفة واسترجاع، مع رفض أنواع الملفات غير المسموحة |
| 5 | Quotes وInvoices التجريبية | دورة quote/invoice كاملة محليًا مع حالات واضحة وتصدير قابل للمراجعة، دون ادعاء محاسبة قانونية |
| 6 | التقويم والبحث والأرشيف | مصادر موحدة وروابط عميقة وبحث شامل وأرشفة متسقة عبر domains |
| 7 | Windows Agent والتحليلات الآمنة | Agent اختياري بسياسة pause/exclusions/retention، دون keylogging أو screenshots أو قراءة محتوى |
| 8 | التقوية قبل قاعدة البيانات | مراجعة security وRTL وaccessibility وresponsive وحالات الفشل وPWA المحلي |
| 9 | Neon وBetter Auth والإنتاج | credentials حقيقية، migrations، remote adapters، مزامنة، جلسات متعددة، واختبارات ownership فعلية |
| 10 | الإطلاق والتوثيق | بوابات release كاملة، backup/restore runbook، توثيق flags والقيود، ونشر معتمد |

## العقد المحلي المركزي

يعرّف `lib/local-first-contracts.ts` العناصر الآتية:

- `LocalScope` يصف المستخدم والـWorkspace والدور. لا يجوز للـlocal adapter إرجاع سجل خارج هذا النطاق.
- `LocalEntityMeta` يوحّد حقول الهوية والتواريخ وملكية المستخدم أو الـWorkspace.
- `LocalRecord` يضيف `syncState` حتى تظل حالة البيانات المحلية واضحة (`local`, `pending`, `synced`, `failed`) بدل إخفاء فشل المزامنة.
- `LocalStorageEnvelope` يثبت نسخة التخزين وتاريخها وقائمة السجلات.
- `LocalRepository` يحدد عمليات القراءة والإنشاء والتعديل والأرشفة والاسترجاع، ويستقبل `LocalScope` في كل عملية.
- دوال `isLocalRecordInScope` و`markLocalRecordPending` و`markLocalRecordSynced` و`markLocalRecordFailed` توفر حواجز وتحديثات حالة قابلة لإعادة الاستخدام.

## حدود المرحلة الأولى

لا تضيف المرحلة الأولى جداولًا أو migrations، ولا تغيّر schema، ولا تربط `DATABASE_URL`، ولا تشغّل `drizzle-kit generate`. كما لا تحوّل العقود إلى ادعاء بأن الموارد أو الفواتير أو بوابة العميل موجودة؛ التنفيذ الفعلي لكل domain مؤجل إلى مرحلته المحددة.

## معيار الاختبار لكل مرحلة

لا تُغلق أي مرحلة بمجرد نجاح TypeScript. يجب تشغيل TypeScript وESLint وWebpack build، ثم اختبار المتصفح للمسارات المتأثرة، ومراجعة RTL وresponsive وaccessibility، وحالات loaded/empty/loading/error، والأرشفة والاسترجاع، ونطاق الملكية عندما تكون الميزة مرتبطة بـWorkspace. أي اعتماد لقاعدة بيانات أو credentials حقيقية يُسجل فقط في المرحلة التاسعة.
